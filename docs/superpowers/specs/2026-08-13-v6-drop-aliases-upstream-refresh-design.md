# Apipoj Skills v6 — drop compatibility aliases, refresh upstream provenance

**Status:** proposed 2026-08-13
**Target version:** 6.0.0 (`manifest.released` = the day it ships)
**Upstream move:** `6acc160e4e0cd062dbbbd7a1b26ae92855edf07e` → `84fdeffd12f2ee307994d1eb6feb48173b6e0502`

## Why

Two things come due at 6.0.0.

`skills/compat/README.md` promises the 21 temporary aliases are supported `ถึงก่อน 6.0.0`. This release keeps that promise. The aliases are already manual-only and add no authority — they disclose the canonical name and forward. Removing them is the published plan, not a new decision.

Second, the retained upstream reference pages under `docs/` are stale. Every one of the 21 carries a banner claiming it holds the content of the pinned upstream commit, and every one of them holds pre-5.1 text instead. v5.1 re-pinned the lock and rewrote the affected skill bodies but never touched `docs/`. Four pages that should exist were never created: `wizard`, `to-questionnaire`, `wait-what`, `writing-for-agents` — the four skills v5.1 added. One page, `writing-great-skills.md`, is an orphan under upstream's old name.

That is a provenance claim the repository cannot currently support, in a project whose discipline is that no unverified result becomes a success claim. The cause is structural: `check-upstream-drift.cjs` verifies mirror files **exist** and never compares their content, so it reports green on stale pages. Fixing the content without fixing the gate would reproduce the same rot at the next re-pin.

## Scope

**In:** delete all 21 compatibility aliases and every reference to them; re-pin upstream to `84fdeff`; regenerate the reference docs from the pin through a new generator; add an offline content-fidelity gate; bump `5.2.0` → `6.0.0`.

**Out:** bucket, router, naming, and authority-model changes. Upstream's `misc`, `personal`, `in-progress`, and `deprecated` buckets stay excluded. No canonical skill is added, removed, or renamed — the roster goes 61 → 40 purely by subtraction of aliases.

No agent-roster change: aliases route to canonical targets that already exist, so the 21 subagents are untouched.

**Branch:** cut fresh from `main` at 5.2.0. The existing `v6-drop-compat-aliases` branch predates the 5.2.0 merge and carries nothing; delete it.

## 3. Reference docs become generated artifacts

`docs/engineering/` and `docs/productivity/` stop being hand-maintained and become generated output, the same way `plugins/spk-codex/` already is.

**New script: `scripts/sync-upstream-docs.cjs`**

- Mirrors upstream `docs/**` 1:1 at the pinned commit. Output is 25 pages: 21 refreshed, 4 added (`wizard`, `to-questionnaire`, `wait-what`, `writing-for-agents`), 1 deleted (`writing-great-skills.md`).
- Each page is the required Thai upstream-reference banner followed by the verbatim upstream body.
- Requires `--from <upstream-checkout>`, reading through `git show <pin>:<path>`. This is a manual, reviewed operation run at re-pin time. It is never part of CI, honoring the `scripts/` guardrail against network access.
- Writes `docs/upstream/reference-hashes.json` as part of the same run, so content and hashes cannot diverge.

**Upstream filenames stay.** After v6, `docs/engineering/implement.md` exists while `/implement` does not. The 1:1 path mapping is what makes provenance comparison mean anything, and renaming would leave the mirror unable to diff against upstream. The banner absorbs the confusion by naming the canonical SPK skill each page corresponds to — `implement.md` says it maps to `/code`. Pages with no canonical counterpart say so.

**Banner contract:** first line is the existing Thai upstream-reference notice; second line names the canonical skill or its absence. `.agents/writing-docs.md` is updated to describe the generated status and the two-line banner.

## 4. Content-fidelity gate

**`docs/upstream/reference-hashes.json`** maps each mirrored path to the sha256 of its post-banner body.

`check-upstream-drift.cjs` gains an offline verification pass that recomputes each file's body hash and compares. It fails on:

- an edited body (hash mismatch),
- a page in the hash file but missing on disk,
- a page on disk but absent from the hash file,
- a hash file whose entries do not match the shipped page set.

The check needs no network and no upstream objects — only the repo's own files — so it runs in `verify:release` and in CI, where no upstream remote is fetched.

**The property this buys:** re-pinning without regenerating now fails the release gate. The exact failure that shipped in 5.1 becomes unshippable.

The existing existence checks and the `--compare <path>` mode stay as they are.

## 5. Verification

Repo convention is TDD with every validation function exported for isolated testing. Each new function in `sync-upstream-docs.cjs` and each new check in `check-upstream-drift.cjs` gets a matching Jest suite in `tests/`, covering the stale-artifact cases the current gate misses:

- body edited after generation → fail
- page deleted from disk → fail
- page added without a hash entry → fail
- hash file stale against the shipped pages → fail
- clean generated tree → pass

Release evidence:

- `npm run verify:release` green, including `verify:coverage`.
- `npm run generate:platforms` produces no diff after commit.
- Roster count assertions read 40 with no alias clause.
- Manual check in a real session: `/start` resolves; two removed names (`/implement`, `/grill-me`) report as nonexistent rather than routing.

## Risks

**Users typing removed names get an error.** That is the intended contract of a major version and the published deprecation plan, and the aliases have disclosed their canonical names for the whole 5.x line. The CHANGELOG carries the full 21-row mapping table so the fix is one lookup away.

**The mirror can only be regenerated with an upstream checkout.** Acceptable: re-pinning already requires reviewing upstream, which requires a checkout. The gate that runs everywhere stays offline.
