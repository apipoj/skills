# Apipoj Skills v5.1 — upstream refresh design

**Status:** approved 2026-08-07
**Target version:** 5.1.0 (`manifest.released` = the day it ships)
**Upstream move:** `2ab958093e83e0ec752e6c1c5932da465bf23e0c` → `6acc160e4e0cd062dbbbd7a1b26ae92855edf07e`

## Why

v5.0 pinned `mattpocock/skills` at `2ab9580`. Upstream has moved 102 commits since. Inside our two promoted buckets that range contains four new skills, one breaking rename, and twelve modified skills. This release reviews that range and adopts the parts that change behavior.

SPK skills are Thai-first rewrites, not ports. "Adopting" upstream means reproducing the **behavior** in our own Thai canonical source and English mirror — never pasting upstream prose.

## Scope

**In:** re-pin the lock, add three new skills, rebase `write-skills` onto `writing-for-agents`, port four substantive behavior changes, bump `5.0.0` → `5.1.0`.

**Out:** upstream wording churn with no behavior change (PRD→spec renaming, de-Claude-ifying tool references such as `Agent tool`/`subagent_type=Explore`, `wayfinder` emphasis markers). Also out: upstream's `misc`, `personal`, `in-progress`, and `deprecated` buckets, which stay excluded. The redaction guidance upstream added to `diagnosing-bugs` is already shipped in `7e7aefe` and needs no work.

No agent-roster change: all three new commands route `direct`, so the 21 subagents are untouched.

## 2. Three new skills

| SPK id | bucket | command | activation | effectLevel | upstream origin |
|---|---|---|---|---|---|
| `wizard` | `operations` | `/wizard` | model-invokable | `workspace_write` | `wizard` |
| `to-questionnaire` | `productivity` | `/to-questionnaire` | manual-only | `workspace_write` | `to-questionnaire` |

**Names stay as upstream.** None of the three carries upstream branding the way `ask-matt` and `setup-matt-pocock-skills` did, and all three are already short. Renaming would buy three more compat aliases and nothing else. Thai identity comes from `locales.th.displayName` and `locales.th.description`, as with every other skill.

**`wizard` goes to `operations`, not upstream's `engineering`.** Provisioning, credentials, and cutovers belong with `deploy`, `doctor`, and `pr`.

**Activation matches upstream.** `wizard` has no `disable-model-invocation`, so the agent can reach for it when it hits a human-only wall — that reach is the point of the skill. `to-questionnaire` and `wait-what` are both `disable-model-invocation: true` upstream and stay manual-only here; `wait-what` in particular is meaningless unless the human fires it.

### Per-skill behavior

**`wizard`** — scope the manual procedure (read `.env*`, `README`, `docker-compose*`, `.github/workflows/*` for every `secrets.*`/`vars.*` reference before asking the user anything), confirm the ordered stage list, author one `stage` per step from the shipped template, then verify and hand off. See section 3 for the envelope.

**`to-questionnaire`** — interview the user about the *send*, not the subject: who receives it, and what the user needs back. Write the questions at the gap between the two, most-important-first, to `to-questionnaire-<slug>.md` in the working directory, and report the path.

**`wait-what`** — re-pitch the last message with the context the user was missing, in plain language, using the `CONTEXT.md` vocabulary. Read-only, no files touched. The Thai body is the natural place for this skill to earn its keep: plain Thai over borrowed jargon is exactly the correction it exists to make.

### Files per new skill

1. `skills/<bucket>/<id>/SKILL.md` — Thai canonical. Frontmatter `name` must equal the id, `description` non-empty, body must contain Thai characters, and the file must not contain `Task(`, `subagent_type`, `spk:`, or `/plugin `.
2. `locales/en/skills/<bucket>/<id>/SKILL.md` — English mirror (mirrors carry `SKILL.md` only).
3. `plugins/spk/skills/<id>/SKILL.md` — Claude runtime payload, English, opening with the Thai-first Experience paragraph and containing `## Workflow`, `## Evidence Receipt`, and `## Guardrails`. `description` must match `locales.en.description` in the contract exactly, and manual-only skills must set `disable-model-invocation: true`.
4. `contracts/workflows.json` — full entry: `tier`, `origin`, `sources`, both locales, `activation`, `effectLevel`, `role`, `workflow` phases, `artifacts`, `evidence`, `guardrails`.
5. `manifest.json` — `commands` entry, `direct: true`.
6. `evals/skilllab-scenarios.json` — `positive`, `nearMiss`, and `outcome` scenarios in both `en` and `th`.

`skills/<bucket>/<id>/agents/openai.yaml` and everything under `plugins/spk-codex/` are generated — `npm run generate:platforms`, never by hand.

The runtime payload ships **`SKILL.md` only** (`plugins/spk/skills/<id>/` has no other files, and the Codex generator copies exactly that one path per skill). Any reference doc must therefore be either folded into the runtime `SKILL.md` or placed under `plugins/spk/templates/`.

## 3. Wizard envelope

SPK's wizard **authors and validates; it never runs the script.**

Process: scope the stages → confirm the list with the user → author from the template → `bash -n`, plus `shellcheck` when available → `chmod +x` → hand the path to the human with instructions.

Guardrails on the contract entry:

- Never execute the generated wizard. It opens browsers and blocks on human input; the human runs it.
- Never echo a captured value back into the transcript. If a secret surfaces while authoring, write `<REDACTED>`.
- Trace statically instead of running: every value named in the scoping step is captured and lands where the scoping step said, and every `set_secret` name matches a `secrets.*` reference in CI.
- `confirm` before every irreversible stage in the generated script.
- Never hand-edit the library above the `STAGES` marker.

This keeps `effectLevel` at `workspace_write`: SPK writes one script file. The `.env` and `gh secret` writes happen under the human's hands, outside the agent's approval surface — which is why this does not need `external_write` and its approval gate.

**Template placement:** `plugins/spk/templates/wizard/template.sh`. `templates` is already in `CODEX_RUNTIME_COPY_ENTRIES`, so both payloads receive it and Codex parity holds. Port upstream's library — `stage`, `say`/`step`, `open_url` (including WSL), `ask`/`ask_secret`, `write_env` (idempotent upsert), `set_secret`/`set_var`, `pause`/`confirm`, stage counter, closing summary — with Thai user-facing strings.

Per `scripts/AGENTS.md`, new shipped scripts need a matching Jest suite: `tests/wizard-template.test.js` asserting the template parses under `bash -n`, still contains the `STAGES` marker, and defines every helper the skill instructs agents to call.

## 5. Behavior ports

**`start`** — replace the "crossing sessions" section with the five-option phase-boundary model: Continue, `/clear`, `/handoff`, subagent, `/compact`, worked top to bottom with first-yes-wins. Continue is ruled out first because every other option converts a primary source into a lossy secondary one; `/compact` sits last as the default rather than the first reach. `/handoff` narrows to four cases: new harness, new directory, a colleague, or forking a side task mid-phase. Smart zone 120k → 150k tokens. New `PHASE-BOUNDARIES.md` beside the Thai source and its English mirror; a condensed version of the tree goes inline in the runtime `SKILL.md`, since reference files do not ship.

**`prototype`** — the logic branch produces a **single shareable HTML file** — free-play buttons plus tabbed guided walkthroughs, driveable by a non-developer, started by double-clicking — instead of a terminal app. The "one command to run" rule becomes "trivial to run": UI prototypes still start from the project task runner; logic demos are the HTML file.

**`asking`** — replace one-question-at-a-time with **rounds over a frontier**. The frontier is every decision whose prerequisites are settled; ask the whole frontier in one round, numbered, each with a recommended answer, in the format:

```
❓ **Q1** - **<title>**: <body>

➡️ <recommended answer>
```

Each round's answers push the frontier outward. Facts are the agent's job — dispatch a sub-agent rather than asking the user, and don't block the rest of the round on it; only questions downstream of that lookup wait. Done when the frontier is empty.

**`tdd`** — add the pointer: when the shape of the interface is itself in question (module depth, seam placement, what the interface exposes), consult `codebase-design` for the vocabulary. It is a reference to read, not a session to run.

## 7. Verification

`npm run verify:release` is the gate — it chains manifest validation, platform-artifact check, docs regen check, version sync, reference integrity, skill descriptions, agent contracts, grep gates, native skills, upstream provenance, SkillLab, release metadata, `npm audit`, and coverage.

Expected to fail first and need attention, in this order: `verify:native` (docs missing the four new `/spk:` ids), `verify:upstream` (pin and count), `verify:metadata` (roster claims), `verify:platforms` (stale generated payload), `eval:skilllab` (missing scenarios).

Plus `npm test` for the two new/changed suites: `tests/wizard-template.test.js` and the updated `tests/upstream-provenance.test.js`.

## Risks

- **Wizard template drift.** The library is 204 lines of bash we now own. The `bash -n` test catches syntax, not behavior; the mitigation is that agents never edit above the `STAGES` marker, which the skill states and the test asserts.
- **`asking` format churn.** The `❓`/`➡️` format is a visible change for anyone used to one question at a time. It is upstream's deliberate move and the Thai text should present it as normal, not as a migration note.
- **Reference files don't ship.** `PHASE-BOUNDARIES.md` and `SKILL-MECHANICS.md` live in the source trees for parity with upstream but never reach a runtime. Whatever the runtime genuinely needs must be inline in the payload `SKILL.md`, or it does not exist at run time.
