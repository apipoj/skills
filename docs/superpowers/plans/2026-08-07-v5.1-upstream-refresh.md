# Apipoj Skills v5.1 Upstream Refresh — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-pin `mattpocock/skills` at `6acc160`, add `wizard` / `to-questionnaire` / `wait-what`, rebase `write-skills` onto `writing-for-agents`, port four behavior changes, and ship 5.1.0.

**Architecture:** Every skill exists in five places that must stay in lockstep — a Thai canonical source, an English mirror, a Claude runtime payload, a `contracts/workflows.json` entry, and a `manifest.json` command — plus a SkillLab scenario. The Codex payload, the `agents/openai.yaml` files, and every generated doc block are produced by scripts and are never hand-edited. Each task below ends with the repo's own gates green and a commit.

**Tech Stack:** Node.js CJS scripts, Jest, JSON contracts, Markdown skill sources, Bash (wizard template).

Spec: `docs/superpowers/specs/2026-08-07-v5.1-upstream-refresh-design.md`

## Global Constraints

- Target version is `5.1.0`. `manifest.released` is the ship date; the newest `CHANGELOG.md` heading must read `## 5.1.0 - <manifest.released>` with the identical date.
- Upstream pin is `6acc160e4e0cd062dbbbd7a1b26ae92855edf07e`.
- Never hand-edit anything under `plugins/spk-codex/`, `.claude-plugin/marketplace.json`, `skills/<bucket>/<id>/agents/openai.yaml`, or any `<!-- SPK-*:start -->` block. Run `npm run generate:platforms` and `npm run regen`.
- Thai canonical `SKILL.md` files must not contain the tokens `Task(`, `Task (`, `subagent_type`, `spk:`, or `/plugin `. The body must contain Thai characters. Frontmatter `name` must equal the skill id.
- Runtime payload `plugins/spk/skills/<id>/SKILL.md` must contain the headings `## Workflow`, `## Evidence Receipt`, and `## Guardrails`; its `description` must equal `contracts/workflows.json` → `locales.en.description` **character for character**; manual-only skills set `disable-model-invocation: true` and model-invokable skills must omit the key entirely.
- Contract locale blocks require `displayName`, `description` (≤1024 chars), `shortDescription`, `defaultPrompt` (≤128 chars), `triggers` (≥2), and `negativeTriggers` (≥2), in both `en` and `th`. `workflow` needs ≥2 phases. `effectLevel` must be one of `read_only`, `workspace_write`, `git_write`, `external_write`, `destructive`.
- Never weaken `scripts/verify-*.cjs` gates, `plugins/spk/scripts/secret-scanner.cjs`, or `plugins/spk/scripts/wiki-secret-scan.cjs` to make a check pass.
- Work on branch `v5.1-upstream-refresh`.

**Known pre-existing debt — do not fix in this release:** 11 English mirrors are byte-identical to their Thai source and 22 contain Thai text. When a task below touches `tdd` or `prototype`, apply the same change to both files in whatever language each file already uses. Do not translate mirrors as a side effect.

```javascript
const childProcess = require('child_process');

const path = require('path');

const TEMPLATE = path.join(__dirname, '..', 'plugins', 'spk', 'templates', 'wizard', 'template.sh');

const REQUIRED_HELPERS = [
  'stage',
  'say',
  'step',
  'open_url',
  'ask',
  'ask_secret',
  'write_env',
  'set_secret',
  'set_var',
  'pause',
  'confirm',
];

describe('wizard template', () => {
  test('exists and is valid bash', () => {
    expect(fs.existsSync(TEMPLATE)).toBe(true);
    expect(() =>
      childProcess.execFileSync('bash', ['-n', TEMPLATE], { stdio: 'pipe' }),
    ).not.toThrow();
  });

  test('defines every helper the wizard skill tells agents to call', () => {
    const source = fs.readFileSync(TEMPLATE, 'utf8');
    for (const helper of REQUIRED_HELPERS) {
      expect(source).toMatch(new RegExp(`^${helper}\\s*\\(\\)`, 'm'));
    }
  });

  test('keeps the STAGES marker that separates the library from authored stages', () => {
    const source = fs.readFileSync(TEMPLATE, 'utf8');
    const markers = source.split('\n').filter(line => line.includes('=== STAGES ==='));
    expect(markers).toHaveLength(1);
  });

  test('sets strict mode and a stage counter', () => {
    const source = fs.readFileSync(TEMPLATE, 'utf8');
    expect(source).toMatch(/^set -euo pipefail$/m);
    expect(source).toMatch(/^TOTAL_STAGES=/m);
  });
});
```

- [ ] **Step 2: Write the Thai reference document**

Create `skills/engineering/start/PHASE-BOUNDARIES.md` in Thai, covering:

- A **phase** is a chunk of work inside a session — the grilling, the implementation, the QA. The definition is fuzzy on purpose: a phase ends when you think "ok, we're done with that."
- The **phase boundary** is the gap between two phases, and it is the only place this decision belongs. Mid-phase there is no decision — continue, or split the remaining work into subagents. Compacting mid-phase makes the agent lose the thread.
- The five options as a table: **Continue** (stay in the session), **`/clear`** (empty the window), **`/handoff`** (write a portable markdown file), **subagent** (own context window, reports back), **`/compact`** (compress and seed a fresh session).
- The tree, worked top to bottom, first yes wins:
  1. **Can you continue?** Yes if the next phase needs this one as a primary source, or if ~150k tokens of smart zone remain. Grilling → implementation is the standard yes. Continue costs nothing and loses nothing, so rule it out first.
  2. **Is the context irrelevant to what comes next?** Then `/clear` — the cheapest move, and not terminal, since the old session stays resumable. Getting this wrong is one-way: you lose the *why*, and reading the diff back doesn't return it.
  3. **Do you need to hand off?** Only for a new harness, a new directory, a colleague, or forking a side task found mid-phase. What it buys is portability. If nothing is travelling, you don't need it.
  4. **Can the task be done AFK?** Tightly scoped, no steering → subagent, leaving this session untouched. Automated review is the standard case.
  5. **Otherwise `/compact`**, with an instruction so the summary keeps what the next phase needs. It is the default, not the first reach — the four questions above it are all cheaper or more precise.
- **Primary and secondary sources** — every move except Continue turns a primary source into a lossy secondary one. Primary: full information, lots of noise, little room. Secondary: lossy, less noise, lots of room. This is why question 1 comes first.
- These are judgement calls; the value is in asking them in order, at the boundary rather than mid-work.

The interview is now a **design tree** worked in **rounds**. Write, in each file's existing language:

- The **frontier** is every decision whose prerequisites are already settled — the questions answerable now without guessing at answers not yet heard.
- Ask the whole frontier in one round. Number each question and give a recommended answer. Then wait.
- Each round's answers reshape the tree: settled decisions push the frontier outward. Recompute and ask the next round. A question that depends on another question still open in this round belongs to a later round.

- Done when the frontier is empty: every branch visited, nothing silently assumed. Don't act until the user confirms shared understanding.
