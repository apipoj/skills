# สร้างตัวช่วยตั้งค่า

เมื่อต้องให้ตัดสินใจหรือยืนยัน ให้ใช้ structured choice prompt ของ host ถ้ามี ถ้าไม่มีให้ใช้ numbered list ตัวเลือกต้องต่างกันจริงและมีข้อแนะนำหนึ่งข้อ ทุก label ต้องบอกผลลัพธ์จริง และตอบแบบ free-form ได้เสมอ

wizard คือ bash script ที่พาคนทำขั้นตอนที่ต้องลงมือเองทีละขั้น งานที่ทำมือแล้วน่าเบื่อ และอธิบายให้ AI ฟังใหม่ทุกครั้งก็น่าเบื่อพอกัน มันเปิด URL ให้ บอกว่าต้องกดอะไร copy อะไร เก็บค่าที่ได้ เขียนลงที่ที่ควรอยู่ (`.env`, GitHub secret) ยืนยันทุกขั้น และบอกว่าเหลืออีกกี่ขั้น

ใช้ตอนตั้งค่า infrastructure, credential, CI secret, กดผ่าน dashboard ของ third-party ที่ไม่คุ้น หรือทำ migration กับ cutover ครั้งเดียวจบ

**ถ้า agent ทำเองได้ ให้ทำเอง** skill นี้มีไว้สำหรับงานที่คนต้องอยู่ในลูปจริง ๆ เท่านั้น

UX ที่ดีมีให้แล้วใน `templates/wizard/template.sh` — ทั้งความคืบหน้าทีละขั้น ประตูยืนยัน การเปิด URL ข้าม platform (รวม WSL) การพิมพ์ความลับแบบซ่อน การ upsert `.env` แบบรันซ้ำได้ การเขียน `gh secret`/`gh variable` และสรุปปิดท้าย **หน้าที่ของคุณคือกำหนดขอบเขตและเขียน stage เท่านั้น** ไลบรารีเหนือ marker STAGES เหมือนกันทุก wizard และความเหมือนนั้นคือจุดประสงค์ ห้ามแก้

wizard เป็นของใช้แล้วทิ้งโดย default สร้างเพื่อรันครั้งเดียว เก็บไว้ใน path ชั่วคราวหรือ `scripts/` แล้วลบเมื่อเสร็จ commit เข้า repo เฉพาะตอนที่ผู้ใช้อยากได้เส้นทางตั้งค่าที่ใช้ซ้ำได้

## ขั้นที่ 1: กำหนดขอบเขต

หาให้ครบว่าคนต้องทำอะไรบ้าง และระหว่างทางต้องเก็บค่าอะไรบ้าง อ่าน repo ก่อน อย่าถามลอย ๆ

- งานตั้งค่า: `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, config ของ framework และ `.github/workflows/*` — ทุกการอ้าง `secrets.*` และ `vars.*` คือค่าที่ wizard ต้องผลิตออกมา
- งาน migration หรือ transition: สถานะปัจจุบัน สถานะปลายทาง และการกระทำที่ย้อนกลับไม่ได้ที่อยู่ระหว่างสองอย่างนั้น

จากนั้นแสดงรายการ stage ตามลำดับพร้อมค่าที่แต่ละ stage ผลิต แล้วให้ผู้ใช้ยืนยัน เขาอาจเพิ่ม ตัด หรือสลับลำดับได้

**เสร็จเมื่อ:** ตั้งชื่อทุก stage ตามลำดับแล้ว และรู้ครบทุกค่าว่า (ก) คนไปเอามาจากไหน (ข) เขียนลงที่ไหน (`.env`, GitHub secret, ทั้งคู่ หรือไม่เขียนเลยเพราะบาง stage เป็นการกระทำล้วน ๆ) และ (ค) เป็นความลับหรือไม่ (ถ้าใช่ต้องพิมพ์แบบซ่อน)

## ขั้นที่ 2: วาดเส้นทางของแต่ละ stage

เขียนเส้นทางที่คนต้องเดินให้แม่นสำหรับทุก stage — เปิด URL ไหน ไปทำอะไรที่นั่น ค่าโผล่ตรงไหน เติมลงตัวแปรไหน เช่น "Dashboard → Developers → API keys → Reveal test key → copy"

ตรงไหนที่ไม่รู้จริงว่า UI ตอนนี้เป็นอย่างไร หรือคำสั่งที่ถูกต้องคืออะไร **ให้บอกตรง ๆ** แล้วถามผู้ใช้หรือไปอ่าน docs อย่าแต่งขั้นตอนที่อาจไม่มีอยู่จริง

**เสร็จเมื่อ:** ทุก stage แปลงเป็นคำสั่งที่คนไม่รู้เรื่องมาก่อนก็ทำตามได้

## ขั้นที่ 3: เขียน wizard

copy `templates/wizard/template.sh` ไปยัง path ปลายทาง แทนที่ stage ตัวอย่างด้วยหนึ่ง `stage` ต่อหนึ่งขั้น เรียงตามลำดับที่ต้องพึ่งพากัน ใช้เฉพาะ helper ในไลบรารี — `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm` — และตั้ง `TOTAL_STAGES` ให้ตรงกับจำนวน stage ที่เขียน

รักษามาตรฐานที่ template วางไว้: เปิด URL ก่อนถามค่าจากหน้านั้น ใช้ `ask_secret` กับทุกอย่างที่เป็นความลับ `write_env` ทุกค่าที่ต้องเก็บ `set_secret` เฉพาะค่าที่ CI ใช้จริง และ `confirm` ก่อนการกระทำที่ย้อนกลับไม่ได้ทุกครั้ง แต่ละ `stage` ล้างหน้าจอ ให้เห็นเฉพาะขั้นปัจจุบัน จึงควรให้หนึ่ง stage ทำเรื่องเดียว ไม่ให้สิ่งที่คนต้องอ่านเลื่อนหายไป **ห้ามแตะไลบรารีเหนือ marker**

## ขั้นที่ 4: ตรวจสอบและส่งมอบ

- รัน `bash -n <script>` และรัน `shellcheck` ถ้ามีในเครื่อง
- `chmod +x <script>`
- **อย่ารันเองจนจบ** มันเปิด browser และหยุดรอคนพิมพ์ ให้ไล่ตรวจแบบ static แทน: ทุกค่าจากขั้นที่ 1 ถูกเก็บครบและไปอยู่ที่ที่ขั้นที่ 1 บอกไว้ และทุกชื่อใน `set_secret` ตรงกับการอ้าง `secrets.*` ใน CI เป๊ะ
- บอกผู้ใช้ว่ารันอย่างไร ถ้าเป็นเส้นทางตั้งค่าที่ใช้ซ้ำได้ ให้ commit และลิงก์จาก README เพื่อให้คนถัดไปรัน script แทนที่จะมาถาม AI ใหม่

## Autonomy Profile

`afk_local` — ทำงานต่อเองได้ถึง effect level ที่ skill นี้ประกาศเท่านั้น และห้ามยกระดับ read-only เป็น write; prompt budget 0, repair budget 3 รอบ ก่อนหยุดต้องบันทึก phase, assumption, evidence, attempts และ next action ที่ทำต่อได้

## Evidence Receipt

คืน `spk.evidence/v1` ที่มี stage-to-value map, path ของ script, ผลลัพธ์ `bash -n` และ `shellcheck`, สิ่งที่ตรวจสอบแบบ static แล้ว, risks และ next action

## ข้อควรระวัง

- ห้ามรัน wizard ที่สร้างขึ้นเอง คนเป็นคนรัน
- ห้าม echo ค่าที่เก็บได้กลับเข้ามาในบทสนทนา ถ้าความลับโผล่ขึ้นมาระหว่างเขียน ให้เขียน `<REDACTED>` แทน
- ห้ามแก้ไลบรารีเหนือ marker STAGES ด้วยมือ
- ใส่ `confirm` ก่อนทุก stage ที่ย้อนกลับไม่ได้
- ถ้าไม่รู้ว่า UI ของ dashboard ตอนนี้เป็นอย่างไร ให้รายงานว่าไม่รู้ อย่าเดา
