# กลไกเฉพาะของ skill

สาขาเฉพาะของ [write-skills](SKILL.md) สำหรับตอนที่เอกสารที่เขียนเป็น skill — frontmatter, การเลือกวิธี invoke และ router skill เรื่องอื่นทั้งหมดของการเขียนอยู่ใน `SKILL.md` ซึ่งใช้ได้กับเอกสารทุกชนิด

## การเลือกวิธี invoke

มีสองทาง แลกกันระหว่างสอง load

- **model-invoked** — skill มี `description` อยู่ agent จึงเรียกเองได้ และ skill อื่นก็เรียกถึงได้ ผู้ใช้ยังพิมพ์เรียกเองได้อยู่เสมอ เพราะ model-invocation **รวม** การเรียกด้วยมือไว้แล้ว การมี description เพิ่มแค่ช่องทางที่ agent ค้นเจอ ไม่เคยตัดช่องทางของคนออก description คือ context pointer ระดับบนสุดของ skill ที่ถูกบังคับให้โหลดอยู่ตลอด เป็น context load ถาวรแลกกับการค้นเจอ
  กลไก: ไม่ต้องใส่ `disable-model-invocation` และเขียน description ที่มุ่งให้ model อ่าน โดยใส่ branch ที่เป็น trigger ให้ครบ (กฎการเขียนตัวชี้ใน `SKILL.md` ใช้เต็มที่)
- **user-invoked** — ตัด description ออกจากสายตาของ agent มีแต่คนที่พิมพ์ชื่อเท่านั้นที่เรียกได้ และไม่มี skill อื่นเรียกถึงได้ ไม่มี context load เลย แต่จ่ายเป็น cognitive load แทน เพราะคนต้องเป็นคนจำเองว่ามี skill นี้อยู่
  กลไก: ตั้ง `disable-model-invocation: true` แล้ว `description` จะกลายเป็นข้อความสำหรับคนอ่าน เป็นสรุปหนึ่งบรรทัด ไม่ต้องมีรายการ trigger

เลือก model-invocation เฉพาะตอนที่ agent ต้องเรียกเองได้จริง หรือ skill อื่นต้องเรียกถึง ถ้ามันถูกเรียกด้วยมืออย่างเดียวเสมอ ให้เป็น user-invoked แล้วไม่ต้องจ่าย context load

เนื้อหาอ้างอิงที่ user-invoked สองตัวต้องใช้ร่วมกันจะอยู่ในตัวใดตัวหนึ่งไม่ได้ เพราะไม่มี description ทั้งคู่จึงเรียกกันไม่ได้ ให้ย้ายไปเป็นไฟล์ธรรมดานอกระบบ skill แล้วให้ทุก skill ชี้มาที่ไฟล์นั้น

## การแยกตามวิธี invoke

นี่คือรอยตัดแบบ invocation ส่วนรอยตัดแบบลำดับขั้นอยู่ใน `SKILL.md`

แยกออกมาเป็น model-invoked skill ตัวใหม่เมื่อมีคำนำที่ชัดพอจะเป็น trigger ของตัวเอง — คำที่คุณใช้จริงในคำสั่งที่พิมพ์ — หรือเมื่อ skill อื่นต้องเรียกถึงมัน คุณจ่าย context load เพิ่มสำหรับ description ที่โหลดตลอด ดังนั้นการเข้าถึงอิสระนั้นต้องคุ้ม

## Router skill

เมื่อ user-invoked skill เยอะเกินกว่าที่คนจะจำไหว cognitive load ที่กองอยู่นั้นแก้ด้วย **router skill** คือ user-invoked skill ตัวเดียวที่ไล่ชื่อ skill อื่น ๆ พร้อมบอกว่าควรหยิบอันไหนเมื่อไร คนจึงเหลือ skill ที่ต้องจำแค่ตัวเดียวแทนที่จะหลายตัว

router ทำได้แค่บอกใบ้ ไม่สามารถเรียก skill เหล่านั้นให้ทำงานได้ เพราะ user-invoked skill ไม่มี description จึงไม่มีอะไรเรียกถึงได้นอกจากคน
