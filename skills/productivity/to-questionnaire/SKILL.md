# สร้างชุดคำถาม

เปลี่ยนเรื่องที่ผู้ใช้ตอบคนเดียวไม่ได้ให้เป็น **ชุดคำถาม** — เอกสาร Markdown ที่ส่งให้คนคนเดียวกรอกแบบ async หรือนั่งกรอกด้วยกันในที่ประชุม คนรับมีความรู้ที่ผู้ใช้ไม่มี ชุดคำถามคือเครื่องมือดึงความรู้นั้นออกมา

## ถามเรื่องการส่ง ไม่ใช่เรื่องเนื้อหา

หลักการเดียวของ skill นี้ สัมภาษณ์ผู้ใช้เฉพาะเรื่อง **การส่ง** ซึ่งเป็นเรื่องที่เขาตอบได้เสมอ — ส่งให้ใคร และต้องได้อะไรกลับมา แล้วคำถามในเอกสารค่อยเล็งไปที่ **ช่องว่าง** ระหว่างสิ่งที่คนรับรู้กับสิ่งที่ผู้ใช้ต้องการ

อย่าถามผู้ใช้เรื่องเนื้อหาที่เขาตอบไม่ได้ นั่นคือเหตุผลที่เขามาใช้ skill นี้ตั้งแต่แรก

## ขั้นที่ 1: ส่งให้ใคร

ถามในรอบเดียว: บทบาทของคนรับ ความเชี่ยวชาญ และความสัมพันธ์กับผู้ใช้ คำตอบนี้กำหนดโทนของเอกสารและปริมาณ context ที่ต้องใส่เข้าไป

**เสร็จเมื่อ:** รู้ว่าคนรับเป็นใคร และเขารู้อะไรที่ผู้ใช้ไม่รู้

## ขั้นที่ 2: ต้องได้อะไรกลับมา

ถามในรอบเดียว: decision หรือข้อเท็จจริงที่ผู้ใช้ตัดสินเองไม่ได้และต้องการจากคนคนนี้

**เสร็จเมื่อ:** ได้รายการที่จับต้องได้ว่าผู้ใช้ต้องเดินออกมาพร้อมตัดสินใจอะไรได้บ้าง

## ขั้นที่ 3: เขียนชุดคำถาม

ร่างคำถามที่เล็งไปที่ช่องว่างจากขั้นที่ 1–2 ตามโครงด้านล่าง เขียนลงไฟล์ `to-questionnaire-<slug>.md` ใน directory ปัจจุบัน (slug มาจากหัวข้อ) แล้วรายงาน path

**เสร็จเมื่อ:** ไฟล์มีอยู่จริง และทุกเรื่องที่ผู้ใช้ระบุในขั้นที่ 2 มีคำถามครอบคลุมแล้ว

## โครงเอกสาร

วางกรอบเอกสารเป็น **ชุดคำถามเพื่อค้นหาข้อมูล** — ผู้ใช้ขาด context ส่วนคนรับมีอยู่ เรียงคำถามจากสำคัญที่สุดก่อน เพราะ async อาจได้ตอบรอบเดียว และจัดกลุ่มใต้หัวข้อ `##` ตามธีมเมื่อคำถามเริ่มเยอะกว่าไม่กี่ข้อ

```markdown
# <ชื่อชุดคำถาม>

**จุดประสงค์:** ทำไมถึงมีเอกสารนี้ และ decision อะไรที่รออยู่

**บริบทที่ควรรู้ก่อนตอบ:** สรุปสั้น ๆ พอให้คนรับตอบได้โดยไม่ต้องถามกลับ

## <ธีมของกลุ่มคำถาม>

1. **<หัวข้อคำถาม>**
   <รายละเอียดคำถาม พร้อมตัวเลือกถ้ามี>

2. **<หัวข้อคำถาม>**
   <รายละเอียดคำถาม>

## อะไรก็ได้ที่เราลืมถาม

<ช่องเปิดให้คนรับเติมสิ่งที่เขาคิดว่าเราควรรู้>
```

## ข้อควรระวัง

- สัมภาษณ์ผู้ใช้เรื่องการส่งเท่านั้น ห้ามถามเรื่องเนื้อหาที่เขาตอบไม่ได้
- ใช้ภาษาไทยที่กระชับเป็นธรรมชาติ และคงชื่อ identifier ทางเทคนิคไว้ตามเดิม
- เขียนเฉพาะไฟล์ชุดคำถาม อย่าแก้ไฟล์อื่นในโปรเจกต์
- ถ้าไม่รู้ว่าคนรับรู้อะไรบ้าง ให้รายงานว่ายังขาดข้อมูล อย่าเดาแทนเขา
